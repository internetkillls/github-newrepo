# Visual Experience Router — choose evidence-bearing representations, not ornament

Use when teaching any subject in which representation choice can affect observation, interpretation, or performance. This is a METHOD module. Apply the existing `method-content-separation.md` firewall: the subject's sources determine objects/terminology; research on multimedia and visual design determines *how* to present them. It is not permission to teach Mayer, UI jargon, design aesthetics, or the Visual Pipeline as disciplinary content.

## RMC-compatible conditional representation gate

Run only gates that matter; do not output an internal stage ledger to the learner.

| Gate | Input / question | Output / exit condition | Failure and repair |
|---|---|---|---|
| V0 Goal | What must the learner perceive, distinguish, predict, produce or argue? | One observable learning move and assessment | Generic image request → locate object/task first |
| V1 Material | What evidence/source/image/code/text exists? Can the tool/version/media be inspected? | Media provenance + availability + uncertainty | Wrong version, fabricated clip, decorative art → retrieve source or make an explicitly labeled schematic |
| V2 Relation | Is the relevant relation spatial, temporal, causal, procedural, quantitative, interpretive, or purely verbal? | Explicit visual semantics or decision to stay textual | Decorative arrow, conflated causation → choose a different form or qualify relation |
| V3 Medium | Which *minimum sufficient* representation exposes that relation? | Text / source image / side-by-side / annotated screenshot / step trace / diagram / video / executable / interactive choice / none | Too many modalities, redundant hero imagery → cut or simplify |
| V4 Action | What can learner DO with this representation? | Observe, predict, compare, manipulate, interpret, verify, teach-back, or explicitly passive when appropriate | Cosmetic click without inference → replace with learner action or plain static media |
| V5 Interaction fidelity | Does the host actually support the requested action, state, feedback, and saved progress? | Honest executable controls, or static fallback / click-through inquiry | Promise of code runner, persistent progress, simulated app screenshots without runtime → downgrade claim |
| V6 Accessibility | Can information be perceived and operations used through alternatives? | Text equivalent; usable navigation and motion controls where implemented | Color-only meaning / unreadable diagram / motion trap → repair before deliver |
| V7 Probe | Does removing the image or interaction make the lesson worse? Does a misconception survive? | One discriminating observation; next exact action | Beautiful but useless → remove/rebuild |

RMC: repair earliest failed prerequisite. Visual Pipeline adaptation: preserve `brief → measurable visual specification → minimal witness → review → verified deliverable` as a conditional method, without importing venue palettes, timing, aesthetics or target engines into ordinary education.

## Media selection by instructional function

- **Definition or theorem**: clear words, worked derivation, proof or counterexample. No mandatory hero image.
- **Visual identification**: real source photograph, artwork, UI screen or instrument with local annotations. State whether screenshot is verified; show source and version.
- **Spatial arrangement**: position-aware sketch, annotated scene, scale and viewpoint; if these are unknown, do not fabricate photorealistic spatial evidence.
- **Data flow**: typed nodes/edges/inputs/outputs with direction and observable state; version check where operator names matter.
- **Motion, transition or embodied performance**: short controlled clip, keyframes, timelines, performance score, or user-driven simulation. Include still frames/transcript and pause if needed; do not make nonessential motion compulsory.
- **Comparing effects**: before/after with the SAME controlled variable or appropriate juxtaposition; do not present unrelated pictures as controlled evidence.
- **Quantitative trends**: honest chart with units, denominators and uncertainty; use table when exact lookup matters more than visual pattern.
- **Contested interpretations**: source passage or object plus alternative readings and anchored warrants, not a single linear 'A causes B' diagram.
- **Skill performance**: a minimal mirrorable demo with starting state, steps, checkpoints, one variable change, observed result and failure diagnosis.
- **When none of these applies**: use text only. The absence of visuals can be an intentional quality choice.

Selection priority is *relevance and provenance*, not screenshot > animation > diagram universally. Authentic source visuals are usually best for identifying actual interfaces/artworks; a drawn analytic schematic can be better than a screenshot for revealing hidden relations.

## Instructional co-location and attention

Place the relevant image/snippet adjacent to the claim and action it serves. Label exactly the feature the learner should attend to, why it matters, and what changing it does. Avoid separate galleries when they force the reader to shuttle memory across distant blocks. Prefer progressive disclosure for optional theory, deeper literature, advanced controls and alternative solutions; DO NOT hide prerequisites, warnings, target state, source status, accessibility tools or feedback needed for the current action. For moving procedures segment by meaning and provide learner-controlled pacing; no one-size-fits-all video duration.

Use one coherent color/shape mapping per diagram; never rely on color alone. Leave sufficient whitespace and readable labels. For dense diagrams, use a simplified overview followed by precise detail and a full text equivalent rather than miniaturizing an illegible network.

## Source distinction and aesthetic integrity

Label media as: `verified source screenshot/photograph` | `original instructional schematic` | `generated interpretation` | `unverified reference`. A generated image cannot verify a historical event, current software UI, published artwork, apparatus, or measured experiment. For art, preserve situated context, author and contested readings; underground or culturally specific aesthetics cannot be reduced to genre decoration. Avoid generic glossy dashboard/card/gradient templates unless those visual forms serve the actual instructional object. Novel aesthetics are not inherently better pedagogy, and repetition can be meaningful in art.

## Visual-spec record (create internally; show to user only when helpful)

```
lesson_id; task_and_success_test; learner_level; subject_source_anchor;
representation_type; why_this_medium; relation_types;
media_origin/license/version; critical_labels; hidden_assumptions;
interactive_actions_supported; host_fallback; expected_observation;
misconception_counterexample; alt_text/long_description;
checkpoint_and_next_action
```

For curriculum diagrams, link stable lesson IDs and actual dependency edges; do not force a linear chronology when the course is a DAG. For design sketches, independent visuals can deliberately be speculative but must be marked as proposals.
