# Course reasoning controller — selective adoption of RMC 0.6.0

RMC is a METHOD controller. Coursecraft is a pedagogy engine, not a reasoner transcript renderer. Adapt the controller's stage discipline, source partition and repair logic; do not copy all RMC technical terminology, philosophical examples or its full bibliography into subject lessons.

## Conditional control loop

`learning task → domain/inquiry route → active learning-design stage → failure signature → smallest licensed action → observable exit test → next stage / earliest-dependency repair`

For each active stage ask: PURPOSE; ENTRY GATE; ALLOWED OPERATIONS; GUARDRAILS; EXIT/HANDOFF. Skip a stage only if its exit has already been satisfied by evidence. For simple requests (e.g., define a known TOP operator), only run gates relevant to accuracy and useful explanation; don't force a nine-step course.

| Gate | Entry | Decision / operation | Observable exit | Earliest repair |
|---|---|---|---|---|
| C0 Intake | request and available history | resolve learner aim, artifacts/constraints, origin, approval status, version | scope and constraints coherent | clarify or narrow before curriculum |
| C1 Route | scope identified | choose software/creative-coding/design/humanities/math/etc and evidence regime (conceptual, empirical, normative, procedural) | evidence of learning matches jurisdiction | re-route if wrong domain or claim type |
| C2 Constitute learning problem | route picked | identify question, performance task, decisive misconception, success criterion and credible rival | task is answerable and checkable | reformulate question, not just wording |
| C3 Decompose dependencies | task coherent | concepts/term-senses, primitives, operations, prerequisites, real constraints, source roles | shortest viable path and actual dependencies explicit | repair missing prerequisite/ambiguous term |
| C4 Design lesson | necessary dependencies present | choose smallest licensed explanation, representation, example, lab and hint | each asset supports a precise learning move | replace nonfunctional diagram/step |
| C5 Discriminating tests | draft lesson and assessment | use counterexample, alternative method, failure case, version check, transfer, teach-back | would show if learner/course claim fails | revisit earliest cause of failure |
| C6 Evidence audit and integrate | source/verification debt exists | verify primary source, authentic task and rights, preserve legitimate uncertainty, join compatible results | claims no stronger than sources, artefact runnable where tested | narrow claim/re-search/mark unverified |
| C7 Closure/handoff | test results and learner action known | capture agreed vs provisional, verified vs attempted, remaining blockers, next exact action | resumable contract and lesson without dead ends | reopen the earliest invalid dependency |

## Failure signature → intervention

- **Jargon replaces a governing problem** → question-backtrack: learner's actual question and falsifiable task before theorists or tools.
- **Concept explained only by near-synonym** → semantic descent: why concept needed, material realization, operational difference, excluded neighbors.
- **Hidden inference from diagram arrow** → warrant expose: relation type, link evidence, and possible counterexample.
- **Conceptual words jump straight to numeric axes** → materialize → relationalize → represent; only then apply measurement/graphical encoding.
- **Any chart/graphic looks too certain** → interpretation audit: sample, source, aggregation, omissions, alternate encoding.
- **Unverified lesson says 'complete'** → runtime/proof witness, learner trace and independent test; downgrade unverified state.
- **Student fails late capstone because a base operation never worked** → trace to first missing prerequisite and branch only there.
- **Two rival explanations/solutions** → preserve competing criteria, run a discriminating comparison, don't average incompatible claims.
- **Method framework dominates domain explanation** → policy-content firewall; remove controller language unless independently warranted.

## Course curriculum governance

Course `DRAFT` can carry an explicit assumption and provisional first lesson. `AGREED` requires learner acceptance; model has no right to assert implied approval. Preserve stable lesson IDs and dependency graph. A `REVISION` should show changed nodes, consequences for verified progress, why revision is proposed, and whether it needs approval. Never erase previously earned evidence merely because a syllabus changes; re-test only when competency mapping changes. Learning contract v1 remains valid; record additional governance metadata as optional supplementary fields or recovery notes. Recompute checkpoints from actual learner actions, not model confidence.

## Evidence jurisdictions

Separate `OBJECT`: subject domain source/evidence; `METHOD`: pedagogy, reasoning, data visualization critique; `EXAMPLE`: authentic reference work or instructor-created synthetic material; `LEARNER`: observed execution/answers; `PROPOSAL`: assistant-added bridges. No source role silently converts to another. If target topic is TouchDesigner, Drucker/Steyerl may regulate diagram policy without becoming required history of TouchDesigner.

## Review trace (when asked for method audit)

Expose a concise decision record: problem/criteria; important alternatives; checked evidence or runnable probe; choice and trade-off; what test would overturn; next action. Never reveal or synthesize private token-by-token thinking.


## Resource and nomenclature gate

C3 and C6 must validate that all core subject signifiers originate in OBJECT/CURRICULUM sources; pedagogic METHOD citations are never substituted. If source discovery yields inadequate coverage, mark curriculum PROVISIONAL and route to course-source-scout. A stage exits on observable adequacy rather than fixed bibliography length.
