# Transcript indexing and evidence-bound decisions (v0.3)

## Scope restriction

`assets/cli/antislop.py index-transcript FILE.jsonl` reads **only** supplied, normalized JSON Lines in chronological order. It does not connect to ChatGPT archives, fetch chats, infer account-wide coverage, transcribe media, or inspect connected sources. The tool is optional; the skill can read authoritatively accessible chat directly. A chat excerpt is not a full export. Never claim account-wide recap from it.

Each line is a JSON object with `message_id` (unique string), `role` (`user`, `assistant`, `tool`, `system`, `developer`) and `content` (plain string). Optional `timestamp`, `thread_id` can be included. If native export is nested, multipart, or has other schemas, normalize it explicitly first and retain a pointer to the original message and any omitted material. Never flatten attached quotes into the user's stance.

Example:

```jsonl
{"message_id":"m1","role":"assistant","content":"We could change the framework."}
{"message_id":"m2","role":"user","content":"Continue the audit, but do not change the framework."}
```

The command yields counts, source locators, and 140-character previews. Those are **index entries only**, not extracted claims, proof of consent, semantic findings, or complete conversational coverage. Indexing is deterministic for the supplied file, not an LLM-free interpretation of its meaning.

## Model extraction, deterministic validation and epistemic checks

1. Human/LLM extracts the *smallest consequential set* of event candidates from indexed messages. Populate `event_id`, `turn_id`, `actor`, `origin`, `kind`, `status`, `text`, `evidence_refs`. Keep transcript locators; preserve user's quotation as `user-quoted` not `user-authored` where applicable. A user's typed message may **contain quotes**, so `role: user` alone is insufficient for commitment.
2. For explicit adoption, link the proposed candidate's `adopted_by` to a later `kind: adoption` event, and link that user event's `target_event_id` (or `target_event_ids`) back to the **same candidate**. `go on` or `yes` by itself can authorize the bounded next step if the local reference is clear but must not be stretched into acceptance of every preceding proposal. When referent is unclear, keep it `unresolved`.
3. For question transition, a new question uses `replaces` to identify its predecessor **only when the transition is warranted**. Distinct threads/scopes may keep multiple active questions. When there are two unlinked active questions in the same scope, retain both and warn rather than silently choosing one.
4. Corrections and retractions use `corrects` to identify the affected event. Without that relation, retain the correction and an unresolved application warning; do not retroactively rewrite everything.
5. Validate with `python assets/cli/antislop.py validate-ledger events.jsonl`; run `verify-anchors events.jsonl --transcript messages.jsonl` to check anchor locators, attributed speaker, message ID and optional exact `quote`; then `recap events.jsonl --coverage coverage.json`. The verifier confirms source-presence only, not interpretation. The coverage file must describe supplied/visible source ranges; `complete_for_requested_range` can only be asserted by a human/tool-supported inventory, never generated by the parser itself.
6. Manually verify that anchors contain the attributed text and that recorded links represent the user's actual meaning. Structural validation CANNOT prove semantic fidelity. Cite decisive cases and report gaps.

## Coverage file example

```json
{"scope_id":"selected-export","requested":"selected discussion about project X","accessible":[{"type":"supplied_file","source_ref":"selected.jsonl","range":"m1..m8"}],"missing":["older threads not exported"],"coverage":"partial","confidence_basis":"source-anchored"}
```

The CLI accepts a manifest with nonempty `accessible` and `coverage` in `partial`, `unknown`, `complete_for_requested_range`; it does not independently verify the claim. A valid manifest is not evidence of completeness by itself.
