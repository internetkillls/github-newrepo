# Nine-class slop audit

Read `../../references/routing-matrix.md` and `../../references/evidence-contract.md`. Classify by **failure mechanism**, not output medium. Run only applicable classes; prioritize invalid task framing and unsupported evidence over presentation. A detected phrase never proves a text is AI-generated or false.

`Q` Query and browsing index: verify question→discriminating query→source role→retrieval→evidence sufficiency; don't mandate novel tokens or adversarial quotas.

`W` Writing: use lexical flags only to focus review, then inspect whether each sentence or passage performs a necessary rhetorical, evidential, aesthetic, or explanatory function; avoid mechanically forcing every sentence to bear a propositional claim.

`L` Linear monolith / dialogue drift: derive from recap; question shift, unaccepted proposal laundering, stale decisions, lost corrections, and no change after feedback.

`S` Sense-making: require term definitions only when inference-bearing and ambiguous; demand a case/mechanism/contrast where appropriate, not universal worked examples for all vocabulary.

`I` Indonesian: check native register, undue calques and specific user constraints; any lexicon needs language- and genre-matched calibration. The source draft's Indonesian lexicon is a proposal, not a built model.

`N` Naming: project glossary and ownership/scope; no blanket predicate-first bigram rule for all code. Test same concept/same identifier and different concept/collision within actual code.

`C` Coding: distinguish static signs from real runtime behavior; meaningful input perturbation and predicted output relations, invariance tests, dependency boundaries, state provenance and test evidence. Never pretend static analysis proves a visual pipeline or source correction works.

`A` Argument: conclusion, premises, warrant and defeaters; test whether inferential weight transfers from cited text. A descriptive→normative transition requires a legitimate normative bridge, which can be stated as an argued principle rather than necessarily a cited normative author.

`M` Mathematics: check interpretation of target, assumptions, types/units, numeric recomputation and proof steps with available tools. SymPy/Lean are optional *conditional* checkers; valid formal proof does not establish that the theorem matches the problem. Round to four decimals only when user/task requests that reporting policy.

Issue types: `CONFIRMED` for directly tested contradiction with anchor, `SUPPORTED-RISK` for reasoned but unresolved material defect, `STYLE-SIGNAL` for lexicon/pattern alone, `UNVERIFIED` for inaccessible proof, `NOT-APPLICABLE`. Repair only flagged dependencies, preserve unaffected valid work, include negative controls for false positives and respect user preference without granting preference the status of universal truth.
