# Domain adapter: same pedagogic contract, different proof of learning

| Route | Fundamental unit | First prototype | Control variable | Evidence | Transfer |
|---|---|---|---|---|---|
| Visual arts/performance | perception, visual grammar, stage relation | one motif three renderings | scale, density, rhythm, spatial position | annotated screen recording, storyboard | multi-screen/performance |
| Software UI/tooling | interface entity and operation | minimal file/project | one UI setting | screenshot + expected state | same task in adjacent feature |
| Creative coding | state, render loop, mapping | one running sketch | one numerical parameter | runnable file + render | alternate geometry/input |
| Programming | types, state, data flow, boundary cases | tiny passing function | one input case | tests and program trace | changed specification |
| Mathematics | definitions, construction, statement, warrant | solve one fully shown example | premise/parameter | derivation + counterexample | new class of problem |
| Empirical research | question, measurement, design, threats | tiny reproducible analysis | sampling/operationalization | protocol + result | new dataset/control |
| Humanities research | problem, text evidence, interpretation, counterargument | annotated short passage | rival reading | provenance and argumentative map | unseen text |
| Operations/business | process, actors, constraints, feedback | simulate one transaction | demand/time/cost | KPI and failure recovery | scaled process |

Every adapter must explicitly map `input → operation → observable state → success criterion` and distinguish conceptual, operational, and evaluative competence.
