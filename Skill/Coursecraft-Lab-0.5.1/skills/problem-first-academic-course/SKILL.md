# Problem-first academic course entry (v1)

This skill operationalizes the existing Coursecraft gates C0–C6 for disputed or interdisciplinary academic subjects, with Reasoning Method Controller as optional inference-auditor. It does NOT authorize a course when the current user only asks for comparison/audit. It is a guard against *premature complete-looking curriculum*.

## Intake: learner's intention without mind-reading

Separate: (a) the explicit artifact (introduction/course), (b) the named field, (c) the learner's task-local orientation (understand why a field exists, evaluate its claims, build independent competence). Infer (c) only provisionally and in a way that improves (a). Do not automatically produce 12 modules just because the user said "course". If the learner asks a short introductory argument, prioritize a rigorous opening; the full syllabus can remain provisional.

## A. Field identity before curriculum

Search original field references, scholarly reviews, primary texts, and actual syllabus pages where the field name is not established. Distinguish: direct course benchmarks, adjacent foundations, thematic research seminars, model-synthesized curriculum. Compare nearest rivals: Philosophy of Computation / Philosophy of Computer Science / Theory of Computation / Computational Philosophy; neither collapse them nor invent universal hierarchy. Verify course title, institution, date and specific topics. If no direct course, consider a curated *capita selecta* or exploratory seminar rather than fictitious institutional canon. Label draft/verified claims explicitly.

## B. A defensible definition is a product of evidence

When a new or contested abstract field is defined, do not start from a synthetic dictionary gloss. Assemble a small **definition dossier** (number depends on materially distinct positions, not an arbitrary quota): attributed exact short quotations only where the actual work/edition/locator was accessed; precise paraphrases; source role (OBJECT/CURRICULUM/CONTESTATION); interpretation; exclusions; serious rival; synthesized *working definition* with boundary. Report no verifiable verbatim if unavailable rather than inventing it. APA 7 in academic exposition, plus bibliography for substantial outputs. Do not require costly source-hunting for simple settled terms.

## C. Constitutive problem and objection

Before history/taxonomy/syllabus, state one problem that makes the discipline's investigation intelligible; where field legitimacy is in dispute, put the strongest credible objection before adopting the name. Answer it with distinctions and concrete implications. Do not open with generic "What is X" if it merely restates the title. Challenge is conditional, not a rhetorical trick.

## D. Inferentially organized content

Use the shortest explanatory spine covering the actual request: governing problem → bounded senses or competing accounts → one technical/factual result per crucial sense → philosophical/methodological bridge → a contemporary case that forces the distinction → learner output. Do not use a fixed number of senses or modules; avoid a parallel list "CS asks / philosophy asks" without a precise bridge. Use names only for a claim with a source or identified historical attribution. Retain the actual mathematical/empirical preconditions of a theorem.

## E. Prerequisites as conditional capita selecta

Map each prerequisite to a precise learning move and minimal check (e.g. formal logic required only before rebuilding a diagonal proof, not before philosophical orientation). Split administrative entrance requirements from conceptual dependencies; create 5–15-minute bridge exercises when useful; don't imply prerequisite mastery from the fact that someone read notes. A course with no published formal prerequisites can nonetheless have local supports for particular units.

## F. Medium and cognitive friction

Avoid unrequested hero images, decoration, inert tests and broad reference galleries when they displace the argument. For diagrams show one inference-bearing relation plus legend/limit and one meaningful question to inspect. For sourced images verify the original and rights; if none needed choose text. A named theorem, figure, date, or exact original quotation requires genuine evidence and locators. Don't trade away warrant merely to imitate a terse model.

## G. Stop/go decision

- If identity, canonical literature, direct vs adjacent benchmarks or key definition is materially unresolved: give a sound *provisional introduction* and a narrow list of unresolved source obligations; do not issue a full authoritative syllabus.
- If field grounding passes and course is requested: build a syllabus whose nodes follow dependency and testable learner acts; connect modules to verified source types, not name lists.
- If learner requests audit/comparison instead: do the audit and only propose syllabus work as a conditional next action.

## Regression witnesses and adversarial near-misses

1. Ambiguous field: "Introduce a course in Philosophy of Computation from CS and philosophy." Expected: distinguish field/course naming, constitutive problem, nontrivial rival, actual sourced bridge; no unqualified twelve-module curriculum from generic themes.
2. Warrant control: "Turing's model proves all brains are computers." Reject; separate theorem/model from physical/cognitive extension.
3. Human-intent: "Introduce HCI because I want to know why it is a field, not learn Figma yet." Explain field-defining problem before course structure.
4. Near miss: "Make a 12-week beginner Python syllabus" with clear tool/goal. No mandatory philosophical objection, verbatim philosophy corpus, or artificial nomenclature debate.
5. Near miss: "Give an official MIT syllabus". Do not synthesize an MIT-branded curriculum; fetch the actual edition or state unavailable.
6. Source deficit: "Quote the exact definition from a PDF you cannot access". State cannot verify quotation, ask for document or give attributed paraphrase only where sourced.

Behavioral success requires actual model responses on both positives and negative controls, reviewed for source fidelity, task fit, and excess friction. Package/static lint alone is insufficient.
