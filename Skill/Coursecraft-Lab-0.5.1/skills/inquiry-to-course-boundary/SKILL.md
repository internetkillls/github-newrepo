# Coursecraft inquiry-to-course boundary (v0.4.1)

Coursecraft is a learning capability, not permission to change the requested artifact. Route the present user speech act before running course-orchestrator. When the user actually requests a course, continue to `../course-orchestrator/SKILL.md` and its `course-reasoning-gates.md`; preserve all existing teaching, source, visual, and learner-performance rules.

## Permission to build a curriculum

`COURSE_REQUESTED`: the current request asks for a syllabus, lesson, learning program, lab sequence, assessment or curriculum revision. Build the requested learning artifact after mapping target capabilities and prerequisites. A mixed request also containing business/research analysis requires that analysis under its own evidence standard; don't silently choose a monetization model for the learner.

`COURSE_AGREED_DEPENDENCY`: a previously accepted task explicitly makes a course dependent on newly obtained domain evidence. Complete the missing economic/research investigation before finalizing lesson order. Record `DRAFT/PROVISIONAL` separately from `AGREED`.

`NONCOURSE_INQUIRY`: an explanation, fact-finding question, comparison, audit, debugging request or request for an illustration is primary. Answer it directly and locally. Coursecraft may contribute a clarifying worked example, a small check, or a diagram when warranted; do not produce an unsolicited multiweek program, capstone, niche choice, or click-to-select curriculum interface.

A plugin mention, a previous assistant recommendation, and a preliminary learner plan are not substitutes for `COURSE_REQUESTED` or actual adoption. Latest specific follow-up takes precedence for output type, while genuine prior constraints remain.

## Economic evidence firewall

For monetization inquiries distinguish platform payouts, brand payments, affiliate/commercial commissions and owned-media sales; do not assume those mechanisms all apply to any named account. State payer, deliverable, triggering condition, country/program eligibility where relevant, production cost, and what source or transaction witness is still needed. Hypothetical `views × RPM` or sponsor scenarios establish arithmetic implications, not representative income or a niche ranking. Mark market hypotheses, data and simulations separately.

## Delivery gate

Ask internally: Is the requested economic/conceptual question already answered? Is the course an explicit requested deliverable? Would a visual/control change an inference or a learner operation? If the answer is no, omit it. No generic 8-week syllabus, radio control, or extra resource gallery solely to signal educational completeness.

## Near-miss negative controls

- Explicit course design request: provide a course, not just an investigative explanation.
- Explicit diagram request: provide a diagram if useful, not a refusal based on anti-slop style constraints.
- Brief definitional question: explain directly; do not run a mandatory empirical investigation.

This gate does not claim automatic runtime enforcement or prohibit pedagogic explanations.
