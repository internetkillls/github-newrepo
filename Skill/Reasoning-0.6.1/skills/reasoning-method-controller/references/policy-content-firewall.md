# Policy-content firewall

This module prevents a reasoning policy from becoming the topic, vocabulary, or rhetorical style of the answer merely because it is salient in the controller.

## Core rule

`POLICY PRESENCE ≠ OBJECT RELEVANCE`.

A controller phrase, source, example, warning, or operator may regulate reasoning without appearing in the answer at all.

## Failure signatures

- **Policy mimicry**: answer prose paraphrases skill instructions.
- **Rider echo**: repeated "this does not prove..." / "do not confuse..." clauses appear because controller riders are salient rather than because the object requires them.
- **Method-source capture**: Chalmers, Bhaskar, Toulmin, Brandom, etc. appear because they license an operation rather than because they are part of the target inquiry.
- **Example capture**: examples used inside the skill reappear as answer examples without independent relevance.
- **Aphorism capture**: memorable controller slogans become theses in the target domain.
- **Guardrail-as-content**: safety/epistemic cautions become a large share of the substantive answer.

## Repair

Before introducing controller-derived vocabulary, ask:
1. Would this concept/source still be selected if the skill had used a different example or wording?
2. Does target evidence or the user's object independently require it?
3. What inferential work does it do in the target, beyond showing caution?

If the answer fails, keep the rule internal.

## Output test

Remove all controller-specific phrases from a draft. If the substantive argument collapses, the controller has likely supplied content rather than merely constrained reasoning.
