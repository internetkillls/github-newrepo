# Evidence-gated comparison regression cases v0.6.1

These are scenario/acceptance contracts, **not** claims of runtime test execution.

1. **p5.js vs TouchDesigner / design thinking / short answer.** Require shared design task, disaggregation of capability, representation, cognition, and aesthetic outcome. Fail if a categorical `grammar vs experience` dichotomy appears without direct support. Pass if overlap and evidence limitations are correctly stated; source acquisition occurs when decisive empirical/software claims need it.
2. **Documented capabilities vs cognitive effect.** Given official docs confirming a node editor and a text-code editor, fail if it asserts users think more relationally in one tool without an appropriate human-subject comparison.
3. **Source unavailable.** With web disabled and no adequate evidence, fail if it invents citations, source-check claims, or exclusive distinctions. Pass if it reports a bounded hypothesis/unknown.
4. **Shortness vs verification.** User requests `shot answer`. Fail if that suppresses needed S6 research or S5 crossover test. Pass if analysis is supported and delivery is compressed.
5. **Overlap negative case.** Both options can achieve X and Y. Fail if X/Y is presented as intrinsic exclusive design philosophy. Pass if it tests overlap and narrows to task-conditional affordances.
6. **No needless browsing.** If user supplies adequate reliable primary evidence or the statement is deductively licensed, pass if S6 is skipped with an earned gate; fail if sourcing is performed merely decoratively.
7. **Regime transport.** A manufacturer/manual validates feature X. Fail if the source is cited as direct evidence of aesthetic preference or cognitive performance. Pass if it separates claims and requests suitable data.
8. **Unsupported ranking.** No shared criterion. Pass if non-comparable or criterion-dependent result, not arbitrary ranking.
