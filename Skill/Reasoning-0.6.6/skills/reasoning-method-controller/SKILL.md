# Reasoning Method Controller v0.6.6 — admissibility-first refinement

RMC is a **reasoning-control policy**, not a worldview, bibliography, ontology, universal checker, transcript judge, fixed step-by-step script, or writing template. Preserve existing route families, conditional S0–S9 stages, original analytic modules, epistemic provenance, and dual closure. The revision changes **control semantics**, not the subject matter of the user's task.

**Primary control:** task → primary route/inquiry regime → relevant stage → failure signature → smallest admissible operator → adequate discriminating test or witness → scoped outcome → advance, narrow, or repair earliest failed dependency. Do not run all stages or all validators by ritual; skip already-satisfied exit tests and irrelevant operations. See `references/stage-machine.md` for the canonical stage descriptions; for complex gating always also read `references/adaptive-admissibility.md`, which has precedence **only for applicability, typed status, control-edge separation, and claim-scoped disposition**, not for route choice or object content. Do not make the new preflight visible by default.

## 1. Applicability before any audit or operator

For a material proposed check, identify its **object and claim** (what precise proposition it tests), **jurisdiction** (logical, empirical, interpretive, normative, mathematical, engineering, attribution, etc.), **required inputs**, **source/witness role**, and **whether a failed result could change the decision**. If no decision-changing function exists, do not launch it. A simple answer normally requires neither external research, a mathematical evaluator, adversarial review nor a long stage trace. `NOT_APPLICABLE` is a successful skip, not an error or proof. Do not interpret absence of non-required evidence as a failure. An open-ended conjecture may be licensed as a conjecture without deductive proof; representing it as a proof is not licensed.

Do not convert absence of execution proof into an allegation that code failed. Likewise, a passed lint, syntactic parser, declared graph, or source inspection is **not** evidence of target runtime success. VCT's Python requirement applies when a VCT mathematical/graph decision materially depends on calculation: call an actual Python runtime in that turn; absent execution, mark computational claims unverified and give no receipt. Standalone RMC theory tasks do not acquire an artificial Python requirement because VCT is installed.

## 2. Two axes: epistemic finding vs operational disposition

**Finding** concerns *one specified claim/witness obligation*: `PASS`, `NOT_APPLICABLE`, `UNVERIFIED`, `CONTRADICTED`, `UNSUPPORTED`, `PROVISIONAL`. These are not confidence scores, probabilities, nor a claim about the complete user's project. `PASS` is only scoped to the test observed; `NOT_APPLICABLE` never certifies the untested claim; `UNVERIFIED` means missing required witness, not refutation; `CONTRADICTED` requires observed conflicting evidence; `UNSUPPORTED` is evaluator/representation incapacity, not falsity; `PROVISIONAL` requires explicit scope, assumptions, remaining debt, and a change condition.

**Disposition** concerns what work or claim is affected: `CONTINUE`, `SKIP_CHECK`, `NARROW_CLAIM`, `WITHHOLD_CLAIM`, `REVISE_PREMISE`, `CHANGE_METHOD`. When restricting action, name the **blocked claim/action** and its witness debt; do not globally freeze unrelated writing, source inspection, local patch creation, teaching, or provisional reporting. A high-risk irreversible external action may require a separate authorization/safety gate; this is not converted into an epistemic claim. Never replace `UNKNOWN` with numeric zero or `NOT_APPLICABLE` with `PASS`.

In particular: no runtime receipt → withhold **'bug fixed'**, not **'patch may be drafted'**. No external source required for a self-contained deduction → skip S6 without an evidence debt. No statistical model for interpretive prose → use the interpretive warrant, do not label mathematics missing. A contradicted prerequisite → repair, do not call it merely unverified. Failure signatures are *candidates* until anchored; avoid detector keyword matches as verdicts.

## 3. Graph semantics and repair

Use a **typed multigraph**, never one indiscriminate topological sort of the full reasoning flow:
- `PREREQUISITE`: a logically required condition before a task/stage can proceed; eligible for DAG and cycle testing when represented with justified directed edges;
- `TRANSITION`: normal conditional S0–S9 control motion; allowed to branch or skip;
- `REPAIR`: conditional return such as S6 → S5 or S8 → earliest failed stage; a cycle of repairs is not a circular logical prerequisite.

Do not infer prerequisite edges from textual paragraph order or stage numbering. An actual cycle among declared prerequisites is a candidate blocking dependency, but cycles of feedback between different stages may be intended. Reopen and revalidate downstream claims only if an upstream assumption/witness actually changed. `runtime/adaptive_gate.py` is an **optional read-only, declared-input helper**, not an automatic universal verification engine. Its truth values are specified by the caller; it cannot establish human interpretation, runtime behavior, provenance validity, or whether a source is genuinely independent.

## 4. Mahajan-informed proportional reasoning (conditional)

`Dimensions`: compare like claim kinds and measurement types; typed dimensions and source roles are necessary but not sufficient validity checks. `Easy cases`: use the smallest boundary, counterexample and near-miss positive control likely to discriminate a live alternative; passing finite tests is not general proof. `Lumping`: group redundant audit operations by shared purpose, **not** distinct epistemic jurisdictions or missing interaction terms. `Taking out the big part`: resolve the most consequential, testable unknown first; never impose arbitrary universal search/test quotas. `Analogy`: record source/target relations, lost structure, and transfer defeater. If an easy case contradicts a candidate, reconsider the **model class**, not merely a parameter threshold (Mahajan's frustum cross term). For citations and limits read `references/adaptive-admissibility.md`.

Use these mathematical heuristics as methods **only when their object model and test regime match the task**. They cannot mechanically measure semantic intent, philosophical adequacy, institutional causality, or creative value. When numerical precision or formal proof is required, approximate heuristics cannot substitute for it.

## 5. Preserve canonical route and stage structure

Primary routes: `RECONSTRUCT/AUDIT`, `RESEARCH/DISCOVERY`, `DESIGN/DEBUG`, `COMPARE/DECIDE`, `FORMALIZE/MEASURE`, `THEORY/CONCEPT`; `MIXED` only for genuinely different jurisdictions, preserved to S7. The stages are S0 INTAKE → S1 ROUTE → S2 FRAME → S3 DECOMPOSE → S4 OPERATE → S5 TEST → [S6 EVIDENCE/WORLD] → S7 INTEGRATE → S8 CLOSURE → S9 DELIVER, with conditional skips and repair. The diagram is **not** a universal required execution path. Route sets the evidence standard; stage selects the current dependency; operator has an input/output type and warrant. See canonical descriptions in `references/stage-machine.md`, plus `references/operator-index.md` and `references/inquiry-admissibility.md`.

At S0 identify the requested artifact, origin, accepted decisions, hard constraints and evidence access. Presence in a user message does not imply authorship, assent, or commitment. At S1 separate inquiry regimes before choosing methods. At S2 preserve the governing question, success criterion, type of claim, and material presuppositions. At S3 descend into only inference-bearing term senses, premises, mechanisms, missing dependencies and source roles; no prose→variables leap. At S4 choose the smallest admissible operator. At S5 use a capable falsifier, serious rival or near-miss case **when it could change the result**. At S6 research only for material source-dependent uncertainty; no ornament, author salience, or METHOD-source substitution for OBJECT evidence. At S7 synthesize across compatible jurisdictions and preserve contradictions. At S8 require claim-relative candidate stability and evidence-topology adequacy, a scoped defeater/change condition; no arbitrary source count. At S9 deliver the requested genre; an explicitly provisional/debt-bearing result may be delivered without a false final verdict.

## 6. Provenance, semantics, and interpretation safeguards

Keep `USER-AUTHORED | USER-QUOTED | THIRD-PARTY | PRIOR-ASSISTANT | GENERATED-PASTE | SOURCE-EXTRACT | UNKNOWN` separate from the actor's **stance**. Current specific user correction takes priority over stale assistant proposals; do not silently turn an assistant recommendation into user agreement. Keep METHOD, OBJECT, CONTEXT and DISCOVERY roles separate: retrieved author familiarity and a bundled method reference cannot substitute for target-specific evidence. Version-check mutable APIs, corpus editions, dated publications, and runnable sources. Do not equate source existence, code compilation, unit-test existence, behavioral runtime success, and deployment.

When an inference-bearing term is contested, descend into governing problem, presupposition, constitutive relations, material/social realization, inferential implications, exclusions, competing conceptual scheme and descriptive/revisionary status. Do not perform this full descent for harmless everyday vocabulary. Orientation bundles are defeasible constructions supported by several compatible moves, not inferences about the user's identity. World/umbrella mapping must return to and potentially alter the original problem; source similarity alone is not structural equivalence. Conceptual possibility, empirical attribution, logical consequence, causal explanation and normative justification require different warrants.

For formalization, **materialize → relationalize → represent/formalize** with source-proven dimensions and admissible transformations. Unexplained scalar scores, automatically named topologies, higher-order theorem applicability, measurement validity, and arbitrary graph centrality are forbidden claim promotions. Separate abduction (candidate discovery), induction (bounded agreement/generalization), deduction (conditional entailment) and execution (observed side effects); never force their linear sequence. See `references/formalization-operators.md`, `references/semantic-depth-and-conceptual-descent.md`, `references/provenance-transport.md`.

## 7. AntiSlop handoff and bounded closure

AntiSlop owns *context reconciliation, failure-signature audit and corpus calibration*, not RMC's governing route or user-task definition. Hand off **only material, evidenced candidates**, with claim ID/type, accessible scope, locator/source version, expected condition, observed counterevidence or missing witness, evaluator limitations, result status, action scope, earliest repair target and one near-miss control. `UNVERIFIED` is an evidence debt, not a confirmed slop defect; `NOT_APPLICABLE` is not an issue. AntiSlop must independently adjudicate before upgrading to `CONFIRMED`. Do not claim this plugin change modifies the separate AntiSlop plugin or activates an inter-plugin automation.

Stop after the smallest sufficient test set passes, or deliver a scoped provisional answer with exact debt. Explicit `BLOCKED` should apply only to a specifically required claim/action that cannot proceed safely or truthfully, never to every downstream task. At S8 preserve meaningful unknowns and a realistic REOPEN condition, not an automatic loop hunting one more source. A runtime receipt means a bounded check ran, not that the reasoning theory or deployed application has been verified.

## 9. Final scoped check

Before delivering: Does the answer preserve the latest user's question and consent? Is each active check applicable, typed and decision-changing? Did any missing witness become a false `FAIL`, or a skipped test a false `PASS`? Is each observable outcome supported by a real receipt or bounded argument? Did a graph feedback edge become a fake prerequisite? Did a candidate operator or method source become object-level proof? Can a narrower answer go through despite a non-critical debt? Did AntiSlop receive a witnessed failure, rather than a suspicious phrase? For serious failures, repair the earliest changed dependency; otherwise stop and deliver.
