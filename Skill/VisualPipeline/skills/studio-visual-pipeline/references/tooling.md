# Tooling, MCP and catalog
Skills are instructions; a working MCP/server and installed application are separate dependencies. Discover capabilities before assuming tools. TDMCP endpoint in the uploaded source was localhost:13316/mcp, but this package does not register an unverified connection. Confirm actual host/transport/version, inspect a harmless project status call, and then use the authorized scope. Do not expose a local control server to the internet merely to support account use.
Blender can use its installed command-line Python workflow or a discovered adapter. p5.js can use a browser preview and a separately validated offline capture/export route. Resolume can use supported REST/MCP for documented composition operations; output mapping remains capability-specific. Use official installed/current API docs.
For one-person studio work, start with project folders + canonical JSON + local SQLite index. Tables: projects(project_id,spec_hash,status,manifest_json). Preserve asset/recipe/variant/render/cue/check records within versioned manifests initially; split into normalized tables when querying across venues warrants it. Stable IDs link venue -> project -> recipe revision -> variant -> render -> check -> cue. SQLite is an index, not an asset store or complete job runner.
The helper uses parameterized SQL and a transaction; re-cataloging the same project/spec updates one record. Another spec hash creates a new version. No remote database, telemetry or account API keys are configured.
Capabilities/connection/production check states should be unknown, inspected, ready, failed or pending with evidence; do not infer readiness from an installed skill.
