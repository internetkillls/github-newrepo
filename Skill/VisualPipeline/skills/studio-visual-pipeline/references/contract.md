# Compact contract v1
The JSON example is independently authored studio input, not the upstream TDMCP format. Required: schema_version, project_id, requirements_status, canvas(face_count,width,height,packing), timing(fps,frame_count,clock), recipe(id,version,seed,parameters,palette), targets, adapters, assets and show(timezone,start,end,sessions,boundaries_approved).
User requirements can be confirmed while aesthetic/technical choices remain draft. A render job uses exact rational fps and integer frame range. This pilot uses integer fps; extending to rational fps requires schema/validator revision.
Coordinates: face index0..3, local u left->right, v bottom->top, perimeter s=face+u. Color inputs are sRGB hex; declare target working/output transforms in the adapter manifest. Packing does not define physical wiring.
Build identity hashes canonical spec and declared asset digests; record adapter versions and engine builds. Do not claim byte-identical media from unpinned runtime stacks. For changed assets regenerate their hashes; compare file contents before rendering. Unknown runtime/build and rights checks remain explicit blockers for final delivery, not for making a draft.
Sessions are offsets in seconds from show start, contiguous, non-overlapping and half-open [start,end). Venue timezone is an IANA identifier. The show-day is the evening date even after midnight. The template's null timezone intentionally prevents accidental wall-clock scheduling.
