# Choose the implementation from the effect

Use built-in nodes for common operations and readable small graphs. Use code on disk for custom math, reusable logic or a profiled advantage. Choose from output requirements, operator availability, maintainability and measured cost, rather than a universal preference for code or nodes.

When topology is uncertain, inspect operators, dimensions and connections, calculate positions, and review a visible layout where available. Do not replace a working readable graph solely to reduce node count. For a novel shader use installed-build boilerplate and verify its uniforms/output convention.

External source files should have stable explicit paths and known sync settings. Verify edit reload and extension reinitialization; preserve state intended to survive reload. Follow `td-general` and family skills. No live connection means source/plan delivery with runtime verification pending.
