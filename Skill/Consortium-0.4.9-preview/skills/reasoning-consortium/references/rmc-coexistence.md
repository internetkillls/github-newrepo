# Coexistence with Reasoning Method Controller

The intended deployment has two reasoning plugins:

```text
Reasoning Method Controller (RMC)
  epistemic and inferential discipline

Reasoning Consortium Controller (RCC)
  execution topology and epistemic-state routing
```

## Division of authority

RCC may decide:
- number and type of worker roles;
- context boundaries;
- independence class;
- room/tab allocation;
- closure/cache/handoff boundaries;
- merge topology;
- invalidation/reopen routing.

RMC may decide inside a worker/merge task:
- inquiry regime/admissibility;
- linguistic/epistemic jurisdiction;
- thematic articulation;
- provenance and transport burden;
- argument/warrant/debtor structure;
- formalization applicability;
- verification and self-audit discipline.

## Anti-capture rules

- RCC must never encode `RMC t0 = worker 0`, `t1 = worker 1`, etc.
- RMC must not broaden a worker's evidence access merely because more sources exist.
- A worker may report that its assigned slice is malformed. RCC then re-partitions rather than forcing completion.
- The merge worker receives typed closures and evidence anchors, not every worker's narrative trace.

## Minimal handoff from RCC to RMC

```text
ROLE
SLICE
INQUIRY/OUTPUT GOAL
ALLOWED CONTEXT
EXCLUDED CONTEXT
KNOWN DEPENDENCIES
INDEPENDENCE REQUIREMENT
ACCEPTANCE CRITERIA
```

RMC then governs reasoning inside that envelope.
