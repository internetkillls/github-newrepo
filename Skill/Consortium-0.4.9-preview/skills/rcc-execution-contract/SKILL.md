# Mandatory RCC execution

Read `../../docs/MANDATORY_EXECUTION_v0.4.8.md` before substantive orchestration. Apply its lifecycle gates in every RCC run. This is required, not opt-in and not restricted to a named retrospective. User/system instructions remain authoritative.

Load actual RMC and AntiSlop instructions at intake, in every worker/follow-up and at merge. Prefer current verified companion skills; otherwise read the pinned source library described in `../../policies/required-controllers.json`. Do not substitute @mentions. Missing mandatory sources block delegation. Pinned snapshots supply instructions, not tool activation; never claim absent companion tools executed.

RCC owns orchestration; RMC owns conditional reasoning/evidence exits; AntiSlop owns scope, commitments and evidence-backed defect/repair checks. Preserve their jurisdictions. Select applicable modules rather than mechanically running every stage/detector. Request decision rationales, tests and provenance, not hidden chain-of-thought.

For local official CLI work, initialize/fill the per-case execution contract, compile every task through `execution packet`, and pass `execution check`. The send wrapper supplies the verified actual controller source ZIP. Queue/deferred dispatch also requires preflight. Source/prompt/version hashes must remain bound; an ambiguous prior send is reconciled, never wrapped and resent.

At each dependency/merge, inspect full required source artifacts and controller-linked claims. Require evidence-backed findings, negative controls, missing access and residuals. Method names and `controllersApplied` self-report do not independently certify compliance. Reopen the earliest responsible slice when an invariant fails.

At closure require original-role I0 retrospective interviews within granted worker-message authority, or explicit unavailable/partial reasons. Save the evidence/provenance index, supported lessons and next-prompt requirements. Missing human/native evidence remains a debt, not an invented PASS; complete source transport with release BLOCKED is retained without reintegration loops.

Structural CLI success is `STRUCTURAL_PRECONDITIONS_MET_REVIEW_REQUIRED`. It does not guarantee model obedience, source semantics, native behavior, human outcomes or deterministic thought. Cloud/custom runners must follow the same procedure but are not magically protected by the Node CLI. Preserve authorization boundaries and declare actual activation/version.


## 0.4.9 reliability addendum

Apply [the reliability contract](../../docs/RELIABILITY_v0.4.9.md). Use current queue operational status; an active scheduler or existing PID alone is not an active browser worker. Exact fresh invocation receipts can establish NOT_SENT_CONFIRMED without task success or automatic retry permission. Uncertain clicked Send still requires original-turn reconciliation. Explicit unused-role provisioning never replaces a committed conversation. New structured reviews may use the explicit JSON output contract; never relax an already-sent file contract. Same-role controller reuse requires the exact proof-pinned prior delivery and unchanged bundle, not an @mention. Default five rooms can be explicitly increased while browser sends remain serial. A saved account update does not hot-patch an installed runtime or migrate existing case helpers.
